image::unix-license-plate.jpg[width=500, align="center"]
[.small]#Quelle: Wikipedia (https://en.wikipedia.org/wiki/Live_Free_or_Die)#

[.step]
* eine Familie von Betriebssystemen mit ähnlicher Architektur und ähnlichen Eigenschaften

== (Kurze) Geschichte von Unix (1)
image::thompson-ritchie.jpg[width=500, align="center"]
[.small]#Quelle: Wikipedia (https://en.wikipedia.org/wiki/Unix)#

[.step]
* 1969: In den Bells Labs (Forschungsabteilung von AT&T) entsteht die erste Version von Unix (entwickelt von Ken Thompson und Dennis Ritchie) => System V Unix (**Linux**, Solaris, HP-UX...)
* 1975: Die University of Berkeley entwickelt ihre eigene Version (auf der Basis der AT&T-Version) => BSD Unix (**macOS**, FreeBSD...)
* 1983: GNU-Projekt wird gestartet.

== (Kurze) Geschichte von Unix (2)
[.step]
* 1980er: Entstehung von vielen kommerziellen Unix-Varianten (z. B. SunOS / Solaris von Sun Microsystems, HP-UX von HP, AIX von IBM, SINIX von Siemens, Xenix von Microsoft, NeXTSTEP von NeXT) und kommerzielle Verbreitung von Unix
* 1991: Linus Torvalds veröffentlicht die erste Version von Linux
* 1990er: Verbreitung von Linux und Entstehung der unterschiedlichen Linux-Distributionen (Redhat, SUSE, Debian...)
* 2001: Apple veröffentlicht die erste Version von macOS (auf der Basis von NeXTSTEP und FreeBSD)
* 2007: Apple veröffentlicht die erste Version von iOS
* seit den 2000ern: Konsolidierung der kommerziellen Unix-Varianten / Ablösung durch Linux

== Philosophie von Unix / Linux
[.step]
* "System von Programmierern für Programmierer"
* Shell ist wichtige Benutzerschnittstelle.
* Kleine Tools können kombiniert werden, um grössere Aufgaben zu lösen => Filter und Pipelines
* Verwendung von ASCII-Text als universelles Datenformat (in Dateien, Netzwerkprotokollen und als Schnittstelle zwischen Programmen)
* Aufgaben können durch Scripts automatisiert werden.
* Ressourcen (wie zum Beispiel angeschlossene Hardware und Netzwerkverbindungen) können als Datei angesprochen werden.

== Dateisystem
[.step]
* Alle Dateien und Verzeichnisse sind in einem Baum angeordnet, der mit `/` (Root-Verzeichnis) beginnt.
* Sie sind durch den _Pfad_ = Liste aller übergeordneter Verzeichnisse + der eigene Name eindeutig identifizierbar.
* _Absoluter_ Pfad: beginnt mit dem Root-Verzeichnis (`/`), _relativer_ Pfad: relativ zum aktuellen Verzeichnis
* Es können sich mehrere Dateisysteme (auf verschiedenen Datenträgern) an verschiedenen Stellen als Unterverzeichnisse in dem Baum befinden (_gemountet_).
* Neben normalen Dateien gibt es auch noch spezielle Pseudo-Dateien: Links, Pipes, Devices, Sockets 
* Alle Dateien und Verzeichnisse sind einem Benutzer und einer Gruppe zugeordnet und besitzen Zugriffsrechte (die nicht für Root-Benutzer gelten).
* Standard für die Baumstruktur: https://en.wikipedia.org/wiki/Filesystem_Hierarchy_Standard[_Filesystem Hierarchy Standard_]

== Benutzer
[.step]
* sind durch eine (normalerweise) eindeutige Nummer bestimmt => _User Identifier_ (UID)
* besitzen jeweils ein eigenes Unterverzeichnis im Verzeichnisbaum => Heimatverzeichnis (_Home Directory_, normalerweise unter `/home` oder `/Users`)
* werden entweder in den Dateien `/etc/passwd` und `/etc/shadow` oder in einem Verzeichnisdienst wie LDAP verwaltet
* sind mindestens Mitglied einer Gruppe => primäre Gruppe
* können in weiteren Gruppen Mitglied sein (in `/etc/group` konfiguriert)
* Benutzer mit der UID 0 (normalerweise `root`) haben Vollzugriff auf das System.

== Was ist eine Shell?
[.step]
* ist das Kommandozeileninterface (_Command Line Interface_ = CLI) von Linux zum Ausführen von Programmen
* besitzt auch eingebaute Befehle, Kontrollstrukturen und Variablen und stellt eine vollständige Programmiersprache dar (siehe Kapitel über Shell-Programmierung)
* mehrere Alternativen: sh, ksh, (t)csh, **bash**, **zsh**, fish


<<<
== Shell - Befehlszeile
[.step]
* besteht aus einem (oder mehreren => Pipelines) Befehl(en), Optionen und Argumenten
* Befehle sind entweder in der Shell eingebaut (z. B. `cd`) oder werden im Suchpfad gesucht (Umgebungsvariable `PATH`) und dann als separate Prozesse ausgeführt.
* Befehle setzen beim Beenden den _Exit Status_ (Erfolg / Fehler) => spezielle Variable `$?`
* Shell beenden: Ctrl-d (oder `exit`)
* laufendes Programm beenden: Ctrl-c

== Shell - Editieren der Befehlszeile
Eingegebene oder aus der Historie zurückgeholte Befehlszeile lässt sich editieren (angegeben sind die Standard-Tastenkombinationen in bash und zsh, lassen sich ändern):

|===
| Springen zum Zeilenanfang / Zeilenende | Ctrl-a / Ctrl-e
| einzelnes Zeichen löschen | Ctrl-d / Backspace
| Wort löschen (Zeichen, die zu einem Wort gehören, lassen sich in der zsh konfigurieren, Variable `WORDCHARS`) | Ctrl-w
| Zeile löschen | Ctrl-u
| gelöschte(s) Zeile / Wort einfügen | Ctrl-y
|===

== Shell - Weitere Features (1)
[.step]
* Befehle können von einer Datei lesen (mit `<`) und ihre Ausgabe in eine Datei schreiben (mit `>`) bzw. an eine bestehende Datei anhängen (mit `>>`).
* Befehle können mit `|` zu _Pipelines_ verkettet werden => Ausgabe des ersten Befehls ist Eingabe des zweiten Befehls.
* Befehle können mit `&` am Ende der Befehlszeile im Hintergrund ausgeführt werden.
* Ctrl-z unterbricht ein laufendes Programm, `bg` schickt es in den Hintergrund, `fg` holt es wieder in den Vordergrund.
* Shell kann Befehle durch Drücken der Tab-Taste vervollständigen (Dateien / Verzeichnisse, Programmnamen, Optionen, Variablen).
* Befehlszeilen können als Aliase abgespeichert werden (mit dem Befehl `alias`).

== Shell - Wildcards (1)
[.step]
* In der Shell kann mit unvollständigen Datei- und Verzeichnisnamen gearbeitet werden => Suchmuster oder _Wildcards_ (auch _Globbing_ genannt)
* werden von der Shell und nicht von den Befehlen ausgewertet
* icon:exclamation-circle[] Maximale Länge der Befehlszeile (bei Linux 2MB) beachten!

== Shell - Wildcards (2)
|===
| Syntax | Bedeutung

| `?` | ein beliebiges Zeichen
| `*` | eine beliebige Anzahl von Zeichen
| `[xyz]` |  eines mehrerer möglicher Zeichen, z. B. die Buchstaben x, y oder z
| `[a-z]` | Bereich von Zeichen, z. B. die Buchstaben a bis z
| `*.{jpg,png}` | Alternativen, z. B. alle Dateien, die entweder auf `.jpg` oder auf `.png` enden
| `!(\*.txt)` (`bash` mit der Option `extglob`) bzw. `^*.txt` (`zsh` mit der Option `extendedglob`) | Negierung, z. B. alle Dateien, die nicht auf `.txt` enden
|===

== Spezielle Dateien
[.step]
* Links: Verweise auf andere Dateien / Verzeichnisse, zwei Arten von Links
[.step]
** harte Links: mehrere Namen für eine Datei (nur innerhalb eines Dateisystems, nicht für Verzeichnisse, Ausnahmen sind `.` und `..` und macOS), nur durch die Anzahl der Links erkennbar
** weiche (symbolische) Links: spezielle Datei mit dem Namen des Ziels als Inhalt
* versteckte Dateien / Verzeichnisse: beginnen mit einem Punkt, werden nur mit `ls -a` angezeigt (Konvention von Shells und Programmen)
* Gerätedateien / Devices: dienen zum Zugriff auf Hardware wie Festplatten (befinden sich im Verzeichnis `/dev`)
* Pipes und Sockets: sind ein Mittel zur Kommunikation zwischen Prozessen (nicht zu verwechseln mit den Sockets zur Netzwerkkommunikation)


<<<
== Spezielle Verzeichnisse
[.step]
* vom Betriebssystem interpretiert (harte Links):
[.step]
** aktuelles Verzeichnis: `.` 
** übergeordnetes Verzeichnis: `..` 
* von der Shell (und manchen Programmen wie Editoren) interpretiert:
[.step]
** eigenes Heimatverzeichnis: `~`
** Heimatverzeichnis eines anderen Benutzers: `~sepp`
** vorheriges Verzeichnis: `-`


<<<
== Zugriffsrechte (1)
[.step]
* separate Zugriffsrechte (auch _Mode_ genannt) für den Besitzer einer Datei / eines Verzeichnisses (_User_), die Gruppe (_Group_) und sonstige Benutzer (_Other_)
* drei unterschiedliche Rechte, als Buchstabe oder als Zahl (Wertigkeit des entsprechenden Bits) dargestellt:
+
|===

| Lesen | r | 4
| Schreiben | w | 2
| Ausführen | x | 1
|===

* Besitzer und Gruppe lassen sich mit den Befehlen `chown` / `chgrp`, die Rechte mit `chmod` ändern (`chown`: nur Root, `chgrp`: nur der Besitzer, der auch Mitglied der neuen Gruppe sein muss oder Root, `chmod`: nur der Besitzer oder Root).


<<<
== Zugriffsrechte (2)
[.step]
* Berechtigungen werden im Gegensatz zu Windows nicht vererbt, sondern werden über eine Maske (die sogenannte _umask_), die bestimmt, welche Rechte neue Dateien / Verzeichnisse **nicht** bekommen sollen, festgelegt).
* numerische Darstellung der Zugriffsrechte
[.step]
** 3 Bits für die Flags SUID (4), SGID (2) und Sticky (1), siehe Folie _Bedeutung der Flags / Bits_
** jeweils 3 Bits für User, Group und Other (mit den Werten 4, 2 und 1, siehe vorherige Folie)
** übliche (oktale) Darstellung: 4 Ziffern = Summen der Bitwerte

== Zugriffsrechte - Beispiel (1)
|===
| Rechte | Binäre Darstellung | Oktale Darstellung | `chmod`-Befehl | Ausgabe von `ls`

| gesetztes SUID-Flag, alle Rechte für den Besitzer, Lese- und Ausführrecht für die Gruppe und keine Rechte für alle anderen
| 100 111 101 000
| 4750
| `chmod u=rwxs,g=rx,o= <Datei>` oder `chmod 4750 <Datei>`
| `-rwsr-x---`
|===


<<<
== Zugriffsrechte - Beispiel (2)
|===
| Rechte | Binäre Darstellung | Oktale Darstellung | `chmod`-Befehl | Ausgabe von `ls`

| gesetztes Sticky-Flag, Schreib- und Leserecht für den Besitzer und die Gruppe und Leserecht für alle anderen
| 001 110 110 100
| 1664
| `chmod u=rw,g=rw,o=tr <Datei>` oder `chmod 1664 <Datei>`
| `-rw-rw-r-T`
|===


<<<
== Bedeutung der Zugriffsrechte
[cols="1,2,2"]
|===
| Recht | Datei | Verzeichnis

| Lesen (r) | Inhalt kann gelesen werden. | Inhalt = Namen der Dateien / Unterverzeichnisse kann gelesen werden.
| Schreiben (w) | Inhalt kann verändert werden. | Dateien / Unterverzeichnisse können angelegt / umbenannt / gelöscht werden, **aber nur wenn auch das Ausführrecht vergeben wurde**.
| Ausführen (x) | Datei kann ausgeführt werden (wenn es sich um ein Programm oder Script handelt). | Auf Dateien / Unterverzeichnisse kann zugegriffen werden, in das Verzeichnis kann gewechselt werden.
|===


<<<
== Bedeutung der Flags / Bits
[cols="1,2,2"]
|===
| Flag / Bit | Ausführbare Datei | Verzeichnis

| Set User ID (SUID) | wird mit den Rechten des Besitzer ausgeführt | -
| Set Group ID (SGID) | wird mit den Rechten der Gruppe ausgeführt | Neu angelegte Dateien / Unterverzeichnisse erben die Gruppe des Verzeichnisses.
| Sticky | - | Dateien / Unterverzeichnisse können nur vom Besitzer (oder Root) gelöscht werden.
|===

== Zeitstempel
[.step]
* Alle Dateien und Verzeichnisse besitzen drei unterschiedliche Zeitstempel:
+
[cols="1,3,1"]
|===
| Zeitstempel | Bedeutung | `ls-Befehl`

| Change Time (_ctime_) | Zeitpunkt der letzten Änderung **der Metadaten** (Anlegen der Datei, Änderung von Eigentümer / Gruppe oder Zugriffsrechten, **aber nicht Änderung des Namens**) | `ls -lc`
| Modification Time (_mtime_) | Zeitpunkt der letzten Änderung **des Inhalts** der Datei / des Verzeichnisse (durch Anlegen, Umbenennen oder Löschen von Dateien / Unterverzeichnissen) | `ls -l`
| Access Time (_atime_) | Zeitpunkt des letzten lesenden Zugriffs (nicht immer aktuell) | `ls -u`
|===
* Mit `touch` lassen sich die mtime und atime von Dateien / Verzeichnissen ändern (eine Datei wird angelegt wenn sie nicht existiert).

== Unterschied Metadaten - Inhalt
[cols="a,a", frame=none, grid=none]
|===
|
--
image::file-metadata-content.svg[width=800, align="center"]
--

|
--
[.step]
* Für jede Datei / jedes Verzeichnis gibt es eine sogenannte _Inode_ (systeminterne Datenstruktur, grüne und blaue Kästchen) mit einer pro Dateisystem eindeutigen Nummer.
* Die Inodes enthalten die Metadaten und verweisen auf den eigentlichen Inhalt der Datei / des Verzeichnisses (graue Kästchen).
* Inhalt eines Verzeichnisses: Zuordnung von Dateinamen zu Inode-Nummern => Name ist **nicht** Teil der Metadaten. +
=> Umbenennen einer Datei / eines Verzeichnisses ändert **nicht** die Change Time. +
=> Man braucht dafür **keine** Schreibrechte auf die Datei, nur auf das Verzeichnis.

== Dateiarchive
[.step]
* Archive sind Dateien, die mehrere Dateien oder ganze Verzeichnisbäume enthalten.
* werden für Backups und zum Übertragen von Dateien / Verzeichnissen (z. B. beim Download von Programmen) verwendet
* Linux kennt zwei gängige Arten von Archiven:
+
[cols="1,5"]
|===

| tar
a|
* "klassisches" Format / Programm für Linux / Unix
* Archive sind unkomprimiert, können aber mit Programmen wie `gzip` oder `bzip2` (oder mit den Optionen `-z` / `-j`) komprimiert werden.
* Dateiendung: `.tar` (unkomprimiert), `.tar.gz` oder `.tgz` bzw. `.tar.bz2` (komprimiert)

| ZIP
a|
* auf Windows das am häufigsten genutzte Format
* Archive sind komprimiert.
* Dateiendung: `.zip`
|===

| `zip -r <Archiv> <Datei(en) / Verzeichnis(se)>`

|

== Prozesse (1)
[.step]
* sind Programme, die vom System ausgeführt werden oder auf ihre Ausführung oder ein Ereignis warten
* sind durch Nummern (_Process Identifier_ = PID) gekennzeichnet
* haben immer einen Eltern-Prozess, von dem sie bestimmte Eigenschaften und Objekte (wie geöffnete Dateien) erben => Baumstruktur
* Wurzel des Baumes ist der `systemd`-Prozess (oder `init` / `launchd`) mit der PID 1 (wird vom System beim Booten gestartet).
* Prozesse werden vom _Scheduler_ verwaltet und abwechselnd dem Prozessor / den Prozessoren (bzw. den Prozessorkernen) zugeteilt.
* sind immer einem Benutzer zugeordnet, dessen Rechte sie bekommen


<<<
== Prozesse (2)
[.step]
* besitzen standardmässig drei verschiedene Ein- / Ausgabekanäle, die sie vom Elternprozess erben: Standardeingabe (_stdin_), Standardausgabe (_stdout_), Standardfehlerausgabe (_stderr_)
* können aus mehreren _Threads_ bestehen
* Prozesse befinden sich immer in einem der folgenden Zustände:
[.step]
** laufend \(R) => Prozess wird gerade ausgeführt oder ist bereit, ausgeführt zu werden (befindet sich in der Warteschlange, Anzahl der Prozesse in der Warteschlange ist die Last des Systems).
** unterbrechbar schlafend (S) => Prozess wartet auf ein Ereignis (z. B. Benutzereingabe, Netzwerk-IO oder Ablauf eines Timers) und kann durch Signale (siehe unten) aufgeweckt werden.
** nicht unterbrechbar schlafend (D) => Prozess wartet auf die Beendigung einer Festplatten-IO-Operation.
** gestoppt (T, t) => Prozess wurde angehalten (durch Ctrl-z in der Shell oder von einem Debugger).
** _Zombie_ (Z) => Prozess ist beendet aber Informationen werden noch im Kernel gehalten (für den Elternprozess).


<<<
== Prozesse - Speicherverwaltung
[.step]
* Jeder Prozess hat seinen eigenen _virtuellen Speicher_ (4GB bei 32-Bit-Systemen, 256TB bei 64-Bit-Systemen).
* Virtueller Speicher ist viel grösser als der physikalische RAM-Speicher (bei 64-Bit-Systemen) => _Paging_
[.step]
** Es werden immer nur die aktuell benötigten Programmteile und Daten im Speicher gehalten.
** Programmteile und Daten werden erst bei Bedarf = beim ersten Zugriff nachgeladen.
** Bei Speicherknappheit werden geänderte, aber nicht mehr benötigte Daten in den Swap-Bereich der Festplatte(n) ausgelagert.
* In dem virtuellen Speicher eines Prozesses befinden sich
[.step]
** Programmcode
** (dynamische) Programmbibliotheken
** Daten (einschliesslich des Stacks)


<<<
== Prozesse - Dämonen
[.step]
* sind Prozesse, die im Hintergrund laufen und Dienste bereitstellen
* werden üblicherweise beim Booten des Systems gestartet
* wichtige Dienste / Dämonen:
+
|===

| `systemd` | Erster Prozess (mit der PID 1), der nach dem Booten eines Systems gestartet wird, startet alle anderen Dämonen / Dienste
| `journald` / `rsyslogd` / `syslog-ng` | zentrales Logging (Logdateien in `/var/log`)
| `crond` | zeitgesteuertes Ausführen von Programmen für jeden Benutzer (wird mit dem Befehl `crontab` konfiguriert)
| `sshd` | Secure Shell Server zum Einloggen über das Netzwerk
|===


<<<
== Prozesse - Signale
[.step]
* sind eine Möglichkeit, bei einem Prozess bestimmte Aktionen auszulösen
* werden mit `kill -<Signal> <PID>` oder in Fehlerfällen vom Betriebssystem selber an einen Prozess geschickt (bei Hintergrundprozessen kann mit `%<Nummer>` anstelle der PID auch die Nummer verwendet werden, die die Shell vergibt)
* Verschiedene Signale bewirken unterschiedliche Aktionen:
+
|===
| Signal | Aktion

| SIGTERM (15) | beendet einen Prozess geordnet (ist der Default von `kill`, Ctrl-c in der Shell)
| SIGKILL (9) | beendet einen Prozess zwangsweise
| SIGSTOP (17) | unterbricht einen Prozess (Ctrl-z in der Shell)
| SIGHUP  (1) | veranlasst einen Dämonen (meistens) zum erneuten Einlesen seiner Konfiguration

|===
