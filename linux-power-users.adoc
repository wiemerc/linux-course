== Was ist Unix?
image::unix-license-plate.jpg[width=500, align="center"]
[.small]#Quelle: Wikipedia (https://en.wikipedia.org/wiki/Live_Free_or_Die)#

[.step]
* eine Familie von Betriebssystemen mit ähnlicher Architektur und ähnlichen Eigenschaften
* auch eine Spezifikation für Betriebssysteme (Single UNIX Specification und POSIX)
* und eine eigene Kultur :-)
* Viele Technologien in der IT haben ihren Ursprung in Unix oder sind durch Unix verbreitet worden: TCP/IP, C/C++, reguläre Ausdrücke, Pipes, hierarchische Dateisysteme.

== (Kurze) Geschichte von Unix (1)
image::thompson-ritchie.jpg[width=500, align="center"]
[.small]#Quelle: Wikipedia (https://en.wikipedia.org/wiki/Unix)#

[.step]
* 1969: In den Bells Labs (Forschungsabteilung von AT&T) entsteht die erste Version von Unix (entwickelt von Ken Thompson und Dennis Ritchie) => System V Unix (**Linux**, Solaris, HP-UX...)
* 1975: Die University of Berkeley entwickelt ihre eigene Version (auf der Basis der AT&T-Version) => BSD Unix (**macOS**, FreeBSD...)
* 1983: GNU-Projekt wird gestartet.

== (Kurze) Geschichte von Unix (2)
[.step]
* 1980er: Entstehung von vielen kommerziellen Unix-Varianten (z. B. SunOS / Solaris von Sun Microsystems, HP-UX von HP, AIX von IBM, SINIX von Siemens, Xenix von Microsoft, NeXTSTEP von NeXT) und kommerzielle Verbreitung von Unix
* 1991: Linus Torvalds veröffentlicht die erste Version von Linux.
* 1990er: Verbreitung von Linux und Entstehung der unterschiedlichen Linux-Distributionen (Redhat, SUSE, Debian...)
* 2001: Apple veröffentlicht die erste Version von macOS (auf der Basis von NeXTSTEP und FreeBSD).
* 2007: Apple veröffentlicht die erste Version von iOS.
* seit den 2000ern: Konsolidierung der kommerziellen Unix-Varianten / Ablösung durch Linux

[.step]

== Philosophie von Unix / Linux
[.step]
* "System von Programmierern für Programmierer"
* Shell ist wichtige Benutzerschnittstelle.
* Verwendung von Text als universelles Datenformat (in Dateien, Netzwerkprotokollen und als Schnittstelle zwischen Programmen)
* Ressourcen (wie zum Beispiel angeschlossene Hardware und Netzwerkverbindungen) können als Datei angesprochen werden.

== Dateisystem
[.step]
* Dateisystem = Komponente im Kernel + Datenstrukturen auf dem Datenträger
* Alle Dateien und Verzeichnisse sind in einem Baum angeordnet, der mit `/` (Root-Verzeichnis) beginnt.
* Sie sind durch den _Pfad_ = Liste aller übergeordneter Verzeichnisse + der eigene Name eindeutig identifizierbar.
* _Absoluter_ Pfad: beginnt mit dem Root-Verzeichnis (`/`), _relativer_ Pfad: relativ zum aktuellen Verzeichnis
* Es können sich mehrere Dateisysteme (auf verschiedenen Datenträgern) an verschiedenen Stellen als Unterverzeichnisse in dem Baum befinden (_gemountet_).
* Neben normalen Dateien gibt es auch noch spezielle Pseudo-Dateien: Links, Pipes, Devices, Sockets 
* Alle Dateien und Verzeichnisse sind einem Benutzer und einer Gruppe zugeordnet und besitzen Zugriffsrechte (die nicht für Root-Benutzer gelten).
* Standard für die Baumstruktur: https://en.wikipedia.org/wiki/Filesystem_Hierarchy_Standard[_Filesystem Hierarchy Standard_]

== Benutzer
[.step]
* sind durch eine (normalerweise) eindeutige Nummer bestimmt => _User Identifier_ (UID)
* besitzen jeweils ein eigenes Unterverzeichnis im Verzeichnisbaum => Heimatverzeichnis (_Home Directory_), normalerweise unter `/home` (oder `/Users` auf macOS)
* werden entweder in den Dateien `/etc/passwd` und `/etc/shadow` oder in einem Verzeichnisdienst wie LDAP verwaltet
* sind mindestens Mitglied einer Gruppe => primäre Gruppe
* können in weiteren (Limit ist meistens 65536) Gruppen Mitglied sein (in `/etc/group` oder in einem Verzeichnisdienst konfiguriert)
* Benutzer mit der UID 0 (normalerweise `root`) haben Vollzugriff auf das System.


<<<
== Gruppen
[.step]
* sind durch eine (normalerweise) eindeutige Nummer bestimmt => _Group Identifier_ (GID)
* werden entweder in der Datei `/etc/group` oder in einem Verzeichnisdienst wie LDAP verwaltet
* Lokale Gruppen (in `/etc/group` verwaltet) können nur Benutzer, *nicht* andere Gruppen enthalten.

== Was ist eine Shell?
[.step]
* ist das Kommandozeilen-Interface (_Command Line Interface_ = CLI) von Linux zum Ausführen von Programmen
* wird gestartet wenn man sich auf der Konsole eines Linux-Systems anmeldet, in einer Desktop-Umgebung ein Terminal-Programm öffnet oder sich über das Netz in ein System einloggt
* besitzt auch eingebaute Befehle, Kontrollstrukturen und Variablen und stellt eine vollständige Programmiersprache dar (siehe _Schreiben von (einfachen) Shell-Skripten_)
* mehrere Alternativen: sh, ksh, (t)csh, **Bash**, **Zsh**


<<<
== Shell - Befehlszeile (1)
image::command-syntax.svg[width=1200, align="center"]
[.step]
* besteht aus einem (oder mehreren => Pipelines) Befehl(en), Optionen und Argumenten
* Syntax in Man Pages, Büchern, Dokumentation... und auch in diesem Kurs:
[.step]
** notwendige Argumente in spitzen Klammern: `<Datei>`
** optionale Argumente in eckigen Klammern: `[-x]`
** Alternativen durch senkrechte Striche getrennt: `Datei|Verzeichnis`
* Optionen starten mit `-` (Kurzform, ein Buchstabe) oder mit `--` (Langform, ein Wort / mehrere Wörter mit Bindestrich verbunden), Konvention der Befehle / Programme.


<<<
== Shell - Befehlszeile (2)
* Befehle sind entweder in der Shell eingebaut (z. B. `cd`) oder werden im _Suchpfad_ gesucht (Umgebungsvariable `PATH`) und dann als separate Prozesse ausgeführt.
* Befehle setzen beim Beenden den _Exit Status_ (Erfolg / Fehler) => spezielle Variable `$?`, 0 bedeutet Erfolg, > 0 bedeutet Fehler (die genauen Werte sind abhängig vom Programm)
* laufendes Programm beenden: Ctrl-c
* Shell beenden: Ctrl-d (oder `exit`)

== Shell - Editieren der Befehlszeile
Eingegebene oder aus der Historie zurückgeholte Befehlszeilen lassen sich editieren. Angegeben sind die Standard-Tastenkombinationen in Bash und Zsh, lassen sich ändern.

[cols="3,1"]
|===
| Springen zum Zeilenanfang / Zeilenende | Ctrl-a / Ctrl-e
| einzelnes Zeichen löschen, vorwärts / rückwärts | Ctrl-d / Backspace
| Wort rückwärts löschen (in der Bash bis zum nächsten Leerzeichen, in der Zsh lässt sich konfigurieren, welche Zeichen zu einem Wort gehörig betrachtet werden (Variable `WORDCHARS`)) | Ctrl-w
| Zeile bis zum Anfang löschen | Ctrl-u
| gelöschte(s) Zeile / Wort einfügen | Ctrl-y
|===

== Shell - Weitere Features (1)
[.step]
* Befehle können von einer Datei lesen (mit `<`) und ihre Ausgabe in eine Datei schreiben (mit `>`) bzw. an eine bestehende Datei anhängen (mit `>>`).
* Befehle können mit `|` zu _Pipelines_ verkettet werden => Ausgabe des ersten Befehls ist Eingabe des zweiten Befehls.
* Befehle können mit `&` am Ende der Befehlszeile im Hintergrund ausgeführt werden.
* Ctrl-z unterbricht ein laufendes Programm, `bg` schickt es in den Hintergrund, `fg` holt es wieder in den Vordergrund.
* Shell kann Befehle durch Drücken der Tab-Taste vervollständigen (Dateien / Verzeichnisse, Programmnamen, Optionen, Variablen).
* Befehlszeilen können als Aliase abgespeichert werden (mit dem Befehl `alias`) oder als Funktionen, siehe Kapitel _Schreiben von (einfachen) Shell-Skripten_.


<<<
== Shell - Weitere Features (2)
[.step]
* Befehl mit seiner Ausgabe ersetzen (_Command Substitution_): `$()`
+
[source,sh]
----
echo "Hallo $(whoami)@$(hostname)"
----
* Befehl als "Datei" für Ein- oder Ausgabe nutzen (_Process Substitution_, wenn man nicht die Standardein- / -ausgabe nutzen kann): `<()` und `>()`
+
[source,sh]
----
diff <(grep bla datei1) <(grep blub datei2)
----

== Shell - Wildcards (1)
[.step]
* In der Shell kann mit unvollständigen Datei- und Verzeichnisnamen gearbeitet werden => Suchmuster oder _Wildcards_ (auch _Globbing_ genannt)
* werden von der Shell und nicht von den Befehlen ausgewertet
* icon:exclamation-circle[] Maximale Länge der Befehlszeile (bei Linux 2MB) beachten!

== Shell - Wildcards (2)
|===
| Syntax | Bedeutung

| `?` | ein beliebiges Zeichen
| `*` | eine beliebige Anzahl von Zeichen
| `[xyz]` |  eines mehrerer möglicher Zeichen, z. B. die Buchstaben x, y oder z
| `[a-z]` | Bereich von Zeichen, z. B. die Buchstaben a bis z
| `*.{jpg,png}` | Alternativen, z. B. alle Dateien, die entweder auf `.jpg` oder auf `.png` enden
| `!(\*.txt)` (Bash mit der Option `extglob`) bzw. `^*.txt` (Zsh mit der Option `extendedglob`) | Negierung, z. B. alle Dateien, die nicht auf `.txt` enden
|===

== Shell - Quoting / Escaping
[.step]
* Die meisten Sonderzeichen haben in der Shell (https://tldp.org/LDP/abs/html/special-chars.html[hier] die vollständige Liste für die Bash) eine besondere Bedeutung.
* zwei Möglichkeiten wenn man sie "normal" verwenden will:
[.step]
** in (einfache oder doppelte) Anführungszeichen setzen (_Quoting_)
** einen umgekehrten Schrägstrich (Backslash) voranstellen (_Escaping_)
* Unterschied zwischen einfachen und doppelten Anführungszeichen:
[.step]
** einfache Anführungszeichen: Alle Sonderzeichen (auch Backslashes) verlieren ihre besondere Bedeutung.
** doppelte Anführungszeichen: Manche Sonderzeichen behalten ihre besondere Bedeutung, insbesondere `$` (Variablenexpansion) und `\` (Escaping), siehe https://www.gnu.org/software/bash/manual/html_node/Double-Quotes.html[hier] für die Details.

* Shell "merkt" sich ausgeführte Befehlszeilen (optional auch dauerhaft in einer Datei) => _Shell-Historie_

* Suchen in der Historie: Ctrl-r

== Konfigurationsdateien
[.step]
* Dateien mit einer Standard-Konfiguration liegen in `/etc`, Dateien mit der benutzerspezifischen Konfiguration liegen im Heimatverzeichnis des Benutzers.
* zwei verschiedene (relevante) Dateien:
[.step]
** `.bash_profile` / `.zprofile` für _Login_-Shells (beim Einloggen in der Desktop-Umgebung oder über SSH / `sudo`): Setzen von Umgebungsvariablen (werden an die interaktiven Shells vererbt) und einmaliges Starten von Programmen beim Einloggen
** `.bashrc` / `.zshrc` für _interaktive_ Shells (**nicht** in Skripten): Setzen von Shell-Optionen, Definition von Aliasen und Funktionen, Konfigurieren des Shell-Prompts


<<<
== `sudo`
[.step]
* Tool, um Befehle als Root / als anderer Benutzer auszuführen: `sudo [-u <Benutzer>] <Befehl>`
* Ohne Befehl aber mit der Option `-i` bekommt man eine Shell mit Root-Rechten bzw. den Rechten des anderen Benutzers.
* wird über die Datei `/etc/sudoers` konfiguriert (welche Benutzer / Gruppen dürfen `sudo` benutzen, ist ein Passwort erforderlich oder nicht, welche Befehle dürfen ausgeführt werden...)
* Anzeigen von Benutzername, UID und Gruppe(n): `id`
* Passwort ändern: `passwd`

| l | symbolischer Link => siehe nächste Folie
| b, c | Gerätedateien => siehe nächste Folie
| p, s | Pipes, Sockets => siehe nächste Folie

== Spezielle Dateien
[.step]
* Links: Verweise auf andere Dateien / Verzeichnisse, zwei Arten von Links
[.step]
** harte Links: zusätzlicher Name für eine bestehende Datei (beide Namen verweisen auf die gleiche Inode), harte Links sind nur innerhalb eines Dateisystems und nur für Dateien möglich, Ausnahmen sind `.` und `..` und macOS), sind nur durch die Anzahl der Links erkennbar
** weiche (symbolische) Links: spezielle Datei, die den Pfad (absolut oder relativ) zum Ziel enthält
* versteckte Dateien / Verzeichnisse: beginnen mit einem Punkt, werden nur mit `ls -a` angezeigt (Konvention von Shells und Programmen)
* Gerätedateien / Devices: dienen zum Zugriff auf Hardware wie Festplatten (befinden sich im Verzeichnis `/dev`)
* Pipes und Sockets: sind ein Mittel zur Kommunikation zwischen Prozessen (nicht zu verwechseln mit den Sockets zur Netzwerkkommunikation)

[.step]
* vom Betriebssystem interpretiert (harte Links):
[.step]
** aktuelles Verzeichnis: `.` 
** übergeordnetes Verzeichnis: `..` 
* von der Shell (und manchen Programmen wie Editoren) interpretiert:
[.step]
** eigenes Heimatverzeichnis: `~`
** Heimatverzeichnis eines anderen Benutzers: `~sepp`
** vorheriges Verzeichnis: `-`

== Zugriffsrechte (1)
[.step]
* separate Zugriffsrechte (auch _Mode_ genannt) für den Besitzer einer Datei / eines Verzeichnisses (_User_), die Gruppe (_Group_) und sonstige Benutzer (_Other_)
* drei unterschiedliche Rechte, als Buchstabe oder als Zahl (Wertigkeit des entsprechenden Bits) dargestellt:
+
|===
| Lesen | r | 4
| Schreiben | w | 2
| Ausführen | x | 1
|===

* Besitzer und Gruppe lassen sich mit den Befehlen `chown` / `chgrp`, die Rechte mit `chmod` ändern (`chown`: nur Root, `chgrp`: nur der Besitzer, der auch Mitglied der neuen Gruppe sein muss oder Root, `chmod`: nur der Besitzer oder Root).


<<<
== Zugriffsrechte (2)
[.step]
* Zusätzlich zu den Berechtigungen für User, Group und Other können feingranularere Berechtigungen (für weitere Benutzer und Gruppen) mit Hilfe von https://www.redhat.com/en/blog/linux-access-control-lists[_Access Control Lists_] (ACLs) vergeben werden (wie bei Windows).
* Berechtigungen werden im Gegensatz zu Windows nicht vererbt, sondern werden über eine numerische Maske (die sogenannte _umask_) festgelegt, die bestimmt, welche Rechte neue Dateien / Verzeichnisse **nicht** bekommen sollen => Wert der Maske wird von 666 (Dateien) bzw. 777 (Verzeichnisse) abgezogen.
* numerische Darstellung der Zugriffsrechte
[.step]
** 3 Bits für die Flags SUID (4), SGID (2) und Sticky (1), siehe Folie _Bedeutung der Flags / Bits_
** jeweils 3 Bits für User, Group und Other (mit den Werten 4, 2 und 1, siehe vorherige Folie)
** übliche (oktale) Darstellung: 4 Ziffern = Summen der Bitwerte
* `stat` zeigt die Zugriffsrechte (auch) numerisch an.

== Unterschied Metadaten - Inhalt
[cols="a,a", frame=none, grid=none]
|===
|
--
image::file-metadata-content.svg[width=800, align="center"]
--

|
--
[.step]
* Für jede Datei / jedes Verzeichnis gibt es eine sogenannte _Inode_ (systeminterne Datenstruktur, grüne und blaue Kästchen) mit einer pro Dateisystem eindeutigen Nummer.
* Die Inodes enthalten die Metadaten und verweisen auf den eigentlichen Inhalt der Datei / des Verzeichnisses (graue Kästchen).
* Inhalt eines Verzeichnisses: Zuordnung von Dateinamen zu Inode-Nummern => Name ist **nicht** Teil der Metadaten. +
=> Umbenennen einer Datei / eines Verzeichnisses ändert die Modification Time des übergeordneten Verzeichnises. +
=> Man braucht dafür **keine** Schreibrechte auf die Datei, nur auf das Verzeichnis.
--
|===


<<<
== Bedeutung der Zugriffsrechte
[cols="1,2,2"]
|===
| Recht | Datei | Verzeichnis

| Lesen (r) | Inhalt kann gelesen werden. | Inhalt = Namen der Dateien / Unterverzeichnisse kann gelesen werden.
| Schreiben (w) | Inhalt kann verändert werden. | Dateien / Unterverzeichnisse können angelegt / umbenannt / gelöscht werden, **aber nur wenn auch das Ausführrecht vergeben wurde**.
| Ausführen (x) | Datei kann ausgeführt werden (wenn es sich um ein Programm oder Skript handelt). | Auf Dateien / Unterverzeichnisse kann zugegriffen werden, in das Verzeichnis kann gewechselt werden.
|===


<<<
== Bedeutung der Flags / Bits
[cols="1,2,2"]
|===
| Flag / Bit | Ausführbare Datei | Verzeichnis

| Set User ID (SUID) | wird mit den Rechten des Besitzer ausgeführt | -
| Set Group ID (SGID) | wird mit den Rechten der Gruppe ausgeführt | Neu angelegte Dateien / Unterverzeichnisse erben die Gruppe des Verzeichnisses.
| Sticky | - | Dateien / Unterverzeichnisse können nur vom Besitzer (oder Root) gelöscht werden.
|===

== Zeitstempel
[.step]
* Alle Dateien und Verzeichnisse besitzen drei unterschiedliche Zeitstempel:
+
[cols="1,3,1"]
|===
| Zeitstempel | Bedeutung | `ls`-Befehl

| Change Time (_ctime_) | Zeitpunkt der letzten Änderung der **Metadaten** (Anlegen der Datei, Änderung von Eigentümer / Gruppe oder Zugriffsrechten, auch Änderung des **Namens** obwohl dieser **nicht** zu den Metadaten gehört, eine Erklärung dazu gibt es https://unix.stackexchange.com/questions/211123/why-does-renaming-a-file-with-mv-command-alter-an-inodes-change-date-time[hier]) | `ls -lc`
| Modification Time (_mtime_) | Zeitpunkt der letzten Änderung des **Inhalts** der Datei / des Verzeichnisse (durch Anlegen, Umbenennen oder Löschen von Dateien / Unterverzeichnissen) | `ls -l`
| Access Time (_atime_) | Zeitpunkt des letzten lesenden Zugriffs (nicht immer aktuell) | `ls -u`
|===
* Mit `touch` lassen sich die mtime und atime von Dateien / Verzeichnissen ändern (eine Datei wird angelegt wenn sie nicht existiert).

== Prozesse (1)
[.step]
* sind Programme, die vom System ausgeführt werden oder auf ihre Ausführung / ein Ereignis warten
* besitzen (zu einem bestimmten Zeitpunkt) eindeutige Nummern => _Process Identifier_ (PID)
* haben immer einen Eltern-Prozess, von dem sie bestimmte Eigenschaften und Objekte (wie geöffnete Dateien) erben => Baumstruktur
* Wurzel des Baumes ist der `systemd`-Prozess (oder `init` / `launchd`) mit der PID 1 (wird vom System beim Booten gestartet).
* Prozesse werden vom _Scheduler_ verwaltet und abwechselnd dem Prozessor / den Prozessoren bzw. den Prozessorkernen zugeteilt.
* sind immer einem Benutzer zugeordnet, dessen Rechte sie bekommen


<<<
== Prozesse (2)
[.step]
* besitzen standardmässig drei verschiedene Ein- / Ausgabekanäle, die sie vom Elternprozess erben: Standardeingabe (_stdin_), Standardausgabe (_stdout_), Standardfehlerausgabe (_stderr_)
* können aus mehreren _Threads_ bestehen, die auf mehreren Prozessoren / Prozessorkernen parallel laufen können
* Prozesse befinden sich immer in einem der folgenden Zustände:
[.step]
** laufend \(R) => Prozess wird gerade ausgeführt oder ist bereit, ausgeführt zu werden (befindet sich in der Warteschlange, Anzahl der Prozesse in der Warteschlange ist die Last des Systems).
** unterbrechbar schlafend (S) => Prozess wartet auf ein Ereignis (z. B. Benutzereingabe, Netzwerk-IO oder Ablauf eines Timers) und kann durch Signale (siehe unten) aufgeweckt werden.
** nicht unterbrechbar schlafend (D) => Prozess wartet auf die Beendigung einer Festplatten-IO-Operation.
** gestoppt (T, t) => Prozess wurde angehalten (durch Ctrl-z in der Shell oder von einem Debugger).
** _Zombie_ (Z) => Prozess ist beendet aber Informationen werden noch im Kernel gehalten (für den Elternprozess).


<<<
== Prozesse - Speicherverwaltung
[.step]
* Jeder Prozess hat seinen eigenen _virtuellen Speicher_ (4GB bei 32-Bit-Systemen, 256TB bei 64-Bit-Systemen).
* Virtueller Speicher ist viel grösser als der physikalische RAM-Speicher (bei 64-Bit-Systemen) => _Paging_
[.step]
** Es werden immer nur die aktuell benötigten Programmteile und Daten im Speicher gehalten.
** Programmteile und Daten werden erst bei Bedarf, d. h. beim ersten Zugriff nachgeladen.
** Bei Speicherknappheit werden geänderte, aber aktuell nicht benötigte Daten in den _Swap_-Bereich der Festplatte(n) ausgelagert und geänderte Daten im _Cache_ (Zwischenspeicher im RAM) in die Dateien geschrieben.
** Falls das nicht ausreicht beendet Linux zwangsweise einzelne Prozesse, die viel Speicher belegen (der sogenannte https://medium.com/@msmkumar.eee/751cf7823de8[_OOM Killer_]).
* In dem virtuellen Speicher eines Prozesses befinden sich
[.step]
** Programmcode (des Programms und von evtl. verwendeten Programmbibliotheken)
** Daten

== Prozesse - Signale (1)
[.step]
* sind eine Möglichkeit, bei einem Prozess bestimmte Aktionen auszulösen
* werden mit `kill -<Signal> <PID>` / `pkill -<Signal> <Name des Prozesses>` oder in Fehlerfällen vom Betriebssystem selber an einen Prozess geschickt (bei Hintergrundprozessen kann mit `%<Nummer>` anstelle der PID auch die Nummer verwendet werden, die die Shell vergibt)
* Verschiedene Signale bewirken unterschiedliche Aktionen, siehe nächste Folie, in _kursiv_ die Signale, die vom Betriebssystem geschickt werden => Prozess wird normalerweise beendet.

[cols="1,4"]
|===
| Signal | Aktion

| SIGTERM (15) | beendet einen Prozess geordnet (ist der Default von `kill`)
| SIGKILL (9) | beendet einen Prozess zwangsweise
| SIGINT (2) | unterbricht einen Prozess (Ctrl-c in der Shell)

| _SIGPIPE_ (13) | Versuch, in eine Pipe zu schreiben, dessen anderes Ende (das Programm, das von der Pipe liest) nicht mehr existiert

== Warum Text?
[.step]
* Sehr viele Daten liegen auch heute noch als Text vor, z. B. Anwendungsdaten (https://en.wikipedia.org/wiki/JSON[JSON], https://en.wikipedia.org/wiki/XML[XML]), Programmcode, Konfiguration (https://en.wikipedia.org/wiki/INI_file[INI-Dateien], https://en.wikipedia.org/wiki/YAML[YAML]), Dokumentation (https://en.wikipedia.org/wiki/Markdown[Markdown], https://en.wikipedia.org/wiki/AsciiDoc[AsciiDoc]).
* Text ist das universelle Datenformat in Linux (Dateien, Ein- und Ausgabe von Programmen).
* Arbeiten mit Text(dateien) ist oft einfacher als mit binären Daten oder Datenbanken (und manchmal auch schneller).
* Linux / Unix hat sehr mächtige Tools zum Arbeiten mit Text, alle Tools können mit Dateien oder in Pipelines (mit der Standardein- / -ausgabe) verwendet werden.
* oft drei Schritte in einer Pipeline: Filtern - Transformieren - Aggregieren

== Suchen - `grep`
[.step]
* durchsucht Dateien, Verzeichnisse (rekursiv) oder die Standardeingabe (in einer Pipeline) **zeilenweise** nach einem festen String oder einem _regulären Ausdruck_ (siehe Folie unten)
* oft der Schritt _Filtern_ in einer Pipeline
* entspricht `WHERE` in SQL
* Aufruf: `grep [Optionen] <Suchstring|regulärer Ausdruck> [<Datei(en)>|<Verzeichnis(se)>]`


<<<
== `grep` - Wichtige Optionen (1)
[cols="1,3,3"]
|===

| `-F` | nach festem String suchen | kann man weglassen wenn Suchstring nur aus Buchstaben und / oder Zahlen besteht
| `-P` | nach regulärem Ausdruck suchen | Regulärer Ausdruck ist ein PCRE, siehe Folie unten.
| `-i` | Gross- / Kleinschreibung nicht beachten |
| `-r` | Verzeichnis(se) rekursiv durchsuchen |
| `-c` | nur die Anzahl der Treffer ausgeben |
|===


<<<
== `grep` - Wichtige Optionen (2)
[cols="1,3,3"]
|===

| `-l` | nur Namen der Dateien ausgeben, die mindestens einen Treffer enthalten |
| `-v` | Zeilen ausgeben, die den Suchstring **nicht** enthalten | Zusammen mit `-l` werden die Namen der Dateien ausgegeben, die mindestens eine Zeile enthalten, die den Suchstring **nicht** enthält.
| `-A<n>`, `-B<n>` | n Zeilen nach / vor jedem Treffer ausgeben (für den Kontext) |
|===

== Reguläre Ausdrücke
[.step]
* sind Muster zur Suche nach und Validierung von Strings
* beschreiben die Struktur eines Strings ohne ihn vollständig anzugeben, ähnlich wie die Wildcards in der Shell
* Beispiel: Grossbuchstabe, gefolgt von einer beliebigen Zahl von Kleinbuchstaben, gefolgt von einer oder mehreren Ziffer(n) => `^[A-Z][a-z]*\d+$`
* können in Editoren (Suchen / Ersetzen), Tools wie `grep` und allen modernen Programmiersprachen genutzt werden
* verschiedene Dialekte, gängigster Dialekt ist _Perl Compatible Regular Expressions_ (PCRE)
* Tutorials: https://developer.mozilla.org/de/docs/Web/JavaScript/Guide/Regular_expressions[Mozilla], https://perldoc.perl.org/perlretut[Perl], https://docs.python.org/3/library/re.html[Python]
* https://developer.mozilla.org/de/docs/Web/JavaScript/Guide/Regular_expressions/Cheatsheet[Cheat Sheet]

== Suchen und Ersetzen - `sed` / `perl`
[.step]
* oft der Schritt _Transformieren_ in einer Pipeline
* `sed` ist geeignet für einfache Fälle, nämlich zeilenweise Verarbeitung und feste Strings.
+
[source,sh]
----
$ sed -e 's/<von>/<nach>/g'
----
* Mit der Option `-i` wird in einer Datei "in-place" ersetzt (gilt für `sed` und `perl`).
+
[source,sh]
----
$ sed -i -e 's/<von>/<nach>/g' <Datei>
----
* `perl` kann nach regulären Ausdrücken suchen, auch über mehrere Zeilen hinweg.
[.step]
** Suchen / Ersetzen mit regulärem Ausdruck.
+
[source,sh]
----
$ perl -pe 's/<von>/<nach>/g'
----
** Suchen / Ersetzen über mehrere Zeilen hinweg, `-0777` bewirkt, dass die Datei nicht zeilenweise sondern "in einem Rutsch" eingelesen wird, mit dem Flag `s` werden mit `.` im regulären Ausdruck auch Zeilenumbrüche getroffen.
+
[source,sh]
----
$ perl -0777 -pi -e 's/<von>/<nach>/gs' <Datei>
----

== Strings aus Zeilen ausschneiden - `cut` / `awk` / `perl`
[.step]
* oft der Schritt _Transformieren_ in einer Pipeline
* entspricht `SELECT` in SQL
* einzelne Spalte(n), mit festem Trennzeichen, `cut` oder `awk`, Spalten-Index `n` startet mit 1, mehrere Spalten durch Komma trennen, Default-Trennzeichen ist bei `cut` der Tabulator bzw. sind bei `awk` _Whitespaces_ (Leerzeichen, Tabulatoren, Zeilenumbrüche)
+
[source,sh]
----
$ cut -d<Trennzeichen> -f<n>
$ awk -F<Trennzeichen> '{print $<n>}'
----
* einzelne Spalte(n), getrennt durch einen regulären Ausdruck, Spalten-Index `n` startet mit 0, mehrere Spalten durch Komma trennen
+
[source,sh]
----
$ perl -F<regulärer Ausdruck> -le 'BEGIN{$, = " "} print $F[<n>]'
----
* regulärer Ausdruck, durch die runden Klammern um den Ausdruck wird der gefundenen String der Variablen `$1` zugewiesen
+
[source,sh]
----
$ perl -nle '/(<regulärer Ausdruck>)/; print $1'
----

== Zeilen nach einem ausgeschnittenen String filtern - `perl`
[.step]
* oft der Schritt _Filtern_ in einer Pipeline
* entspricht `WHERE` in SQL
* Zeilen ausgeben, bei denen eine bestimmte Spalte einem regulären Ausdruck entspricht
+
[source,sh]
----
$ perl -F<regulärer Ausdruck> -le 'print if $F[<n>] =~ /<regulärer Ausdruck>/'
----
* regulären Ausdruck numerisch vergleichen, Vergleichsoperatoren sind `==`, `!=`, `<`, `>`, `\<=`, `>=`
+
[source,sh]
----
$ perl -nle '/(<regulärer Ausdruck>)/; print if $1 == <Zahl>'
----

== Sortieren - `sort`
[.step]
* sortiert die angegebene Datei oder die Standardeingabe, mit der kompletten Zeile als Schlüssel
* oft der letzte Schritt in einer Pipeline
* entspricht `ORDER BY`, ggf. mit `DISTINCT` in SQL
* Aufruf: `sort [Optionen] [Datei]`
* Wichtige Optionen
+
[cols="1,3"]
|===

| `-u` | nur unterschiedliche Zeilen / Werte ausgeben
| `-r` | absteigend sortieren
| `-n` | numerisch sortieren
| `t<Trennzeichen> -k<n>` | nach Spalte `n` sortieren, Spalten getrennt durch das angegebene Trennzeichen (Default: Whitespaces)
|===

== Aggregieren
[.step]
* oft der letzte Schritt in einer Pipeline
* verschiedene Möglichkeiten:
[.step]
** Zeilen zählen: (`COUNT()` in SQL): `wc -l`
** nur unterschiedliche Zeilen zusammen mit ihrer Häufigkeit ausgeben (`GROUP BY` mit `COUNT()` in SQL): `uniq -c`, Zeilen müssen bereits sortiert sein
** Zeilen aufsummieren (`SUM() in SQL`): `awk '{sum += $0} END{print sum}'`, Zeilen dürfen nur aus Zahlen bestehen

== Dateien / Verzeichnisse vergleichen - `diff` / `comm`
[.step]
* Dateien vergleichen: `diff <Datei 1> <Datei 2>` (mit der Option `-w` werden Unterschiede in den _Whitespaces_ (Leerzeichen, Tabulatoren, Zeilenumbrüche) ignoriert)
* Ausgabe von zwei Befehlen vergleichen (mit Process Substitution): `diff <(<Befehl 1>) <(Befehl 2)>`
* Verzeichnisse (rekursiv) vergleichen: `diff -r <Verzeichnis 1> <Verzeichnis 2>`
* Zeilen ausgeben, die nur in der ersten / zweiten Datei vorkommen (Dateien müssen sortiert sein): `comm -23 <Datei 1> <Datei 2>` / `comm -13 <Datei 1> <Datei 2>`
* Alternative zu `diff` mit schönerer Ausgabe: https://terminaltrove.com/delta/[`delta`]
* entspricht `MINUS` in SQL (mehr oder weniger)

== Shell-Skripte
[.step]
* sind eine Folge von Befehlen mit Argumenten und Optionen
* eventuell ergänzt um Variablen und Kontrollstrukturen
* können Kommentare enthalten, starten mit `#` und gehen bis zum Ende der Zeile
* werden von der Shell genauso ausgeführt wie interaktiv eingegebene Befehle (mit allen Features wie Pipelines, Ein- / Ausgabeumleitung und Hintergrundprozesse)
* stellen eine vollständige Programmiersprache dar, sind aber nur bedingt für größere Programmieraufgaben geeignet (besser Python oder Perl verwenden)
* Die einzelnen Shells implementieren unterschiedliche "Dialekte", die nicht vollständig kompatibel sind => Auf Linux (und auch macOS) sollte man (unabhängig von der Shell, die man interaktiv nutzt) die Bash für Skripte nutzen.

== Variablen
[.step]
* können Strings oder Ganzzahlen speichern, sind aber eigentlich typlos (auch Zahlen werden intern als Strings gespeichert und Strings können ohne Fehler in arithmetischen Ausdrücken verwendet werden)
* Zusätzlich gibt es auch Listen und Maps (Schlüssel-Wert-Paare), die wir aber in diesem Kurs nicht behandeln.
* müssen nicht deklariert werden

[source, shell]

$ s=abc  <1>
$ x=1
$ nlines=$(wc -l /tmp/blablub.txt)  <2>

$ (( x=$x+1 ))  <4>
$ echo "x = $x"  <5>
----
<1> Zuweisung, wenn der String Leerzeichen enthält muss man Anführungszeichen verwenden.
<2> Ausgabe des Befehls wird der Variablen zugewiesen.
<3> Zugriff auf den Wert durch das vorangestellte Dollarzeichen
<4> Arithmetik, Variablen, die einen String enthalten, werden in 0 umgewandelt.
<5> _Variablenexpansion_ => Wert der Variablen wird in den String eingesetzt, nur in Strings, die durch doppelte Anführungszeichen begrenzt sind.

== Kontrollstrukturen (1)
[.step]
* Verzweigungen führen abhängig von einer oder mehreren Bedingung(en) bestimme Anweisungen aus (einen Codeblock): `if` – `elif` - `else`
* Schleifen wiederholen bestimmte Anweisungen.
* Es gibt zwei Arten von Schleifen in der Shell:
[.step]
** Schleife läuft solange eine Bedingung erfüllt ist: `while`
** Schleife läuft (_iteriert_) über alle Elemente einer Sequenz: `for`
* Möglichkeiten für eine Sequenz:
[.step]
** Aufzählung von Werten im Skript (getrennt durch Leerzeichen)
** Dateien / Verzeichnisse, die mit einem Wildcard-Ausdruck gefunden werden

== Kontrollstrukturen (2)
[.step]
* Dinge, die bei `if` und `while` als Bedingung verwendet werden können:
[.step]
** Vergleiche von Variablen mit einem Wert => Folie _Vergleichsoperatoren_
** Tests von Verzeichnissen und Dateien => Folie _Tests_
** Exit-Status von Programmen
* Bedingungen lassen sich mit `!` negieren.
* Bedingungen lassen sich mit `&&` (und) bzw. `||` (oder) verknüpfen.

== Verzweigungen
[source,sh]
----
if [[ $x < 0 ]]; then  <1>
    echo "x ist kleiner 0 ($x)"  <2>
elif [[ $x > 0 ]]; then  <3>
    echo "x ist grösser 0 ($x)"
else  <4>
    echo "x ist gleich 0 ($x)"
fi  <5>
----
<1> Erste Verzweigung startet mit `if`, gefolgt von der Bedingung in doppelten eckigen Klammern, gefolgt von einem Strichpunkt und `then`.
<2> Codeblock kann aus einer oder mehreren Zeile(n) bestehen.
<3> Weitere Verzweigungen können folgen und starten mit `elif`.
<4> Es kann einen `else`-Zweig geben, der ausgeführt wird, wenn keine der anderen Bedingungen erfüllt ist (nach `else` folgt **kein** `then`).
<5> Die Struktur wird mit `fi` abgeschlossen.

== `for`-Schleifen
[source,sh]
----
for name in Alice Bob Charlie; do  <1>
    echo "Hallo $name"  <2>
done  <3>
for file in *.txt; do  <4>
    ...
done
----
<1> Schleife mit festen Werten, `name` ist die Schleifenvariable, der nacheinander die Werte zugwiesen werden. Der Codeblock wird mit `do` eingeleitet.
<2> Codeblock kann aus einer oder mehreren Zeile(n) bestehen.
<3> Die Schleife wird mit `done` abgeschlossen.
<4> Schleife mit Wildcard

== `while`-Schleifen
[source,sh]
----
x=5
while [[ $x -ge 0 ]]; do  <1>
    echo $x  <2>
    (( x=$x-1 ))
done  <3>
while IFS= read -r line; do  <4>
    ...
done < bla.txt
----
<1> Schleife mit einer Bedingung. Der Codeblock wird mit `do` eingeleitet.
<2> Codeblock kann aus einer oder mehreren Zeile(n) bestehen.
<3> Die Schleife wird mit `done` abgeschlossen.
<4> Schleife, die Zeilen aus einer Datei (oder mit Process Substitution von einem Programm) liest, solange bis alle Zeilen gelesen wurden / das Programm sich beendet). `line` ist die Schleifenvariable, der nacheinander die Zeilen zugewiesen werden (`IFS=` bewirkt, dass Whitespaces am Anfang / Ende der Zeile erhalten bleiben, mit `-r` bleiben Backslashes erhalten).

== Vergleichsoperatoren
[.text-left]
Die allgemeine Syntax ist `[[ <Variable> <Operator> <Wert> ]]`.

|===
| Gleichheit / Ungleichheit | `==` / `!=`
| Prüfen, ob eine Variable einen bestimmten String enthält | `== \*<String>*`, String in Anführungszeichen wenn er Leerzeichen enthält
| Vergleich mit einem regulären Ausdruck (nicht PCREs sondern eine abgespeckte Variante) | `=~`
| grösser / kleiner | `-gt` / `>` / `-lt` / `<`
| grösser gleich / kleiner gleich | `-ge` / `-le`
|===

[.text-left]
Zusätzlich zu den Vergleichen gibt es auch noch Tests, die Dateien / Verzeichnisse auf bestimmte Eigenschaften testen. Die allgemeine Syntax ist `[[ <Test> <Datei oder Verzeichnis> ]]`.

[cols="3,1"]
|===
| Existiert die Datei / das Verzeichnis? | `-e`
| Ist die Datei wirklich eine Datei? | `-f`
| Ist das Verzeichnis wirklich ein Verzeichnis? | `-d`
| Ist die Datei vom Benutzer ausführbar? | `-x`
|===

[.step]

<4> Aufruf der Funktion wie ein Programm

fi
cd $1 || exit 1  <4>
for entry in *; do
    if [[ -d $entry ]]; then
        num_files=$(find $entry -type f | wc -l)
        used_space=$(du -hs $entry | cut -f1)
        echo "Unterverzeichnis $entry enthält $num_files Dateien und belegt $used_space Plattenplatz"
    fi
done
----
<1> Wurde das Skript mit einem Argument aufgerufen (`$#` enthält die Anzahl der Argument)?
<2> `$0` ist der Name des Skripts.
<3> Beenden des Skripts mit dem _Exit Status_ 1
<4> Wenn `cd` fehlschlägt (weil das Verzeichnis nicht existiert oder der Benutzer keine Berechtigung hat) wird `exit` ausgeführt (Abkürzung für `if ! cd ...`).

== Netzwerk - Allgemeines
[.step]
* Die Netzwerk-Funktionalität in Linux wird implementiert durch
[.step]
** Netzwerk-Interfaces = Hardware (z. B. Netzwerk-Karte) + Gerätetreiber im Kernel
** Netzwerk-_Stack_ im Kernel, der die Protokolle wie IP und TCP implementiert
** Dämonen, die Netzwerkdienste wie Web Server oder SSH bereitstellen
* "Netzwerklaufwerke" werden in Linux normalerweise über das _Network File System_ (NFS) realisiert, auch Windows Shares (CIFS) werden unterstützt.


<<<
== Konfigurieren des Netzwerks
[.step]
* Netzwerk-Interfaces besitzen eine oder mehrere IP-Adresse(n) und die zugehörige(n) Netzwerk-_Route(n)_ (Gateways).
* Interfaces werden normalerweise automatisch / dynamisch (über das DHCP-Protokoll) konfiguriert.
* _Namensauflösung_ (Zuordnung von Host- / Rechnernamen zu IP-Adressen) erfolgt normalerweise durch das _Domain Name System_ (DNS), die verwendeten DNS-Server werden auch über DHCP konfiguriert.
* Alternativ kann das Netzwerk auch manuell / statisch konfiguriert werden:
[.step]
** Konfigurationsdateien für die Konfiguration der Interfaces, Dateiname(n) und Format sind abhängig von der Linux-Distribution (z. B. Ubuntu / Debian: `/etc/network/interfaces`, Redhat / CentOS / Fedora: `/etc/sysconfig/network-scripts/ifcfg-ethX`) bzw. der zur Verwaltung des Netzwerks verwendeten Software (z. B. https://wiki.archlinux.org/title/NetworkManager[_NetworkManager_] oder https://wiki.archlinux.org/title/Systemd-networkd[_systemd-networkd_]).
** Zuordnung von Host- / Rechnernamen zu IP-Adressen in der Datei `/etc/hosts` (heute nur noch selten genutzt)
** Datei `/etc/resolv.conf` für die Konfiguration der DNS-Server.


<<<
== Zugriff auf auf einen entfernten Rechner - SSH (1)
[.step]
* Die _Secure Shell_ (SSH) ermöglicht das Arbeiten auf einem über das Netzwerk verbundenen Rechner.
* Man kann sich einloggen und interaktiv (in der Shell) arbeiten oder einzelne Befehle ausführen: `ssh <Benutzer>@<Hostname oder IP-Adresse> [<Befehl>]`
* Authentifizierung erfolgt mit Password oder einem kryptografischen Schlüssel.
[.step]
** Man erzeugt sich ein Schlüsselpaar, bestehend aus einem öffentlichen und einem privaten Schlüssel mit dem Befehl `ssh-keygen` => die Dateien `id_rsa` (privat) und `id_rsa.pub` (öffentlich) im Verzeichnis `~/.ssh/`.
** Den privaten Schlüssel muss man geheim halten (Berechtigung 0700 für das Verzeichnis und 0600 für die Datei) und man sollte ihn mit einer _Passphrase_ sichern.
** Der öffentliche Schlüssel muss in die Datei `~/.ssh/authorized_keys` auf dem **Zielrechner** eingetragen werden (kann mit dem Befehl `ssh-copy-id` gemacht werden).
* Auch Rechner (Hosts) besitzen ein Schlüsselpaar, der öffentliche Schlüssel wird beim ersten Einloggen automatisch in die lokale Datei `~/.ssh/known_hosts` eingetragen.


<<<
== Zugriff auf auf einen entfernten Rechner - SSH (2)
[.step]
* Mit der SSH können auch Dateien übertragen / kopiert werden:
[.step]
** `scp` (wie mit `cp`)
+
[source,sh]
----
$ scp <lokale Datei> <Benutzer>@<Hostname oder IP-Adresse>:<Pfad auf dem Zielrechner>
----
** interaktiv mit `sftp` (wie mit `ftp`)
* Komfortablere und mächtigere Alternative (basiert auf SSH): `rsync`
[.step]
** nur Unterschiede / Änderungen werden übertragen
** sehr viele zusätzliche Optionen
** gut geeignet für Backups oder zum Synchronisieren von mehreren Systemen

== Netzwerk - Weitere wichtige Befehle (1)
|===

| Netzwerk-Interfaces mit MAC-Adresse, IP-Adresse(n) und Netzmasken auflisten +
(Namen, z. B. `eth0`, sind abhängig vom Hardware-Typ und der Linux-Distribution) | `ip addr`

== Starten und Stoppen eines Systems
[.step]
* Ein Linux-System befindet sich zu jedem Zeitpunkt in einem bestimmten Zustand, dem sogenannten _Run Level_ oder _Target_.
* Mit dem Befehl `reboot` wird ein System gebootet (Run Level 6), mit `poweroff` heruntergefahren (Run Level 0).


<<<
== Starten und Stoppen eines Systems - Run Levels
[cols="1,1,3"]
|===
| Run Level | Name | Beschreibung

| 0 | Halt| System ist angehalten / ausgeschaltet.
| 1 | Single User Mode | System läuft, aber nur mit den notwendigen Diensten und ohne Netzwerk, für Wartungsarbeiten.
| 3 | Multi User Mode | System läuft mit allen (konfigurierten) Diensten und dem Netzwerk, aber ohne GUI, Standard für Server.
| 5 | Graphical Mode | wie 3 + GUI (Desktop-Umgebung), Standard für Arbeitsrechner
| 6 | Reboot | System wird gebootet.
|===


<<<
== Starten und Stoppen eines Systems - `systemd` (1)
[.step]
* Beim Booten eines Systems wird nach dem Start des Kernels ein Prozess mit der PID 1 gestartet: `systemd` (`launchd` auf macOS). Dieser Prozess
[.step]
** konfiguriert das System (Devices, Netzwerk, Namensauflösung)
** startet die Dienste (Dämonen), die im Verzeichnis `/etc/systemd/system` bzw. `/etc/systemd/user` für jeden Run Level / jedes Target konfiguriert sind (als symbolische Links in einem Verzeichnis `<Name des Targets>.wants/`).
** stoppt diese Dienste wieder, wenn das zugehörige Run Level / Target verlassen wird
** startet Dienste im Fehlerfall (Prozess hat sich beendet) automatisch neu


<<<
== Starten und Stoppen eines Systems - `systemd` (2)
[.step]
* Vielfältige Konfigurationsmöglichkeiten pro Dienst (in den sogenannten _Unit Files_):
[.step]
** Run Level / Target, in dem der Dienst laufen soll
** Umgebungsvariablen
** Skripte / Programme, die vor / nach dem Starten / Stoppen ausgeführt werden sollen
** Limits für Ressourcen (CPU, Speicher, Plattenplatz)
* Befehl zum Verwalten von Diensten (Starten, Stoppen, Anzeigen des Status...): `systemctl`

== `systemd` Timers (1)
[.step]
* bieten die Möglichkeit, Programme / Skripte periodisch zu bestimmten Zeiten auszuführen (von `systemd`), auch wenn der entsprechende Benutzer nicht eingeloggt ist
* dienen oft dazu, Wartungsarbeiten (z. B. Backups, Löschen von temporären Dateien) automatisch auszuführen
* werden mit den Rechten des jeweiligen Benutzers ausgeführt
* ersetzen auf modernen Linux-Systemen die _Cron Jobs_


<<<
== `systemd` Timers (2)
[.step]
* zwei Konfigurationsdateien pro Programm / Skript:
[.step]
** Konfiguration des Programms / Skripts (welches Programm / Skript, Optionen, Umgebungsvariablen) => `<Name>.service`
+
[source,ini]
----
[Service]
Type=oneshot
ExecStart=/usr/bin/find /tmp -mtime +30 -delete
----
** Konfiguration der Zeit(en), zu der / denen das Programm / Skript ausgeführt werden soll (in https://man7.org/linux/man-pages/man7/systemd.time.7.html[diesem] Format)=> `<Name>.timer`
+
[source,ini]
----
[Timer]
OnCalendar=*-*-* 20:00:00

[Install]
WantedBy=timers.target
----

== `systemd` Timers (3)
[.step]
* können systemweit (Dateien unter `/usr/lib/systemd/system/`, editieren mit `systemctl edit --full --force <Datei>`) oder für einen Benutzer (Dateien unter `~/.config/systemd/user/`, editieren mit `systemctl --user edit --full --force <Datei>`) angelegt werden
* Ausgaben (Standardausgabe / Standardfehlerausgabe) werden vom `journald`-Dämonen gesammelt und können mit `journalctl` angeschaut werden.
* Gute Anleitungen: https://wiki.archlinux.org/title/Systemd/Timers und https://unix.stackexchange.com/a/688512

== Logging (1)
[.step]
* Logmeldungen vom Kernel, von den Diensten und von Benutzern werden vom `journald`-Dämonen gesammelt und (in binärer Form) in Dateien unter `/var/log/journal` geschrieben (max. 10% des verfügbaren Plattenplatzes oder 4GB).
* können mit `journalctl` angeschaut / ausgegeben werden (auch als JSON)
* viele Filtermöglichkeiten, unter anderem
+
|===

| Zeitraum | `--since` (`-S`) / `--until` (`-U`)
| Dienst | `--unit` (`-u`)
| _Facility_ (`kern`, `user`, `auth`, ...) | `--facility`
| Priorität (von `debug` bis `emerg`) | `--priority` (`-p`)
|===

[.step]

* Unter Umständen gibt es auch noch Logdateien unter `/var/log`.

== Datenträger und Dateisysteme
[.step]
* Datenträger (Festplatten, Disk Arrays, CDs / DVDs, USB-Sticks) werden über Gerätedateien (im Verzeichnis `/dev`) angesprochen.
* Datenträger müssen ein von Linux unterstütztes Dateisystem verwenden (ext4, FAT32, ISO 9660...).
* Das _Einhängen_ (_Mount_) macht den Datenträger als Unterverzeichnis (den _Mount Point_) im Verzeichnisbaum sichtbar, der umgekehrte Vorgang ist das _Aushängen_ (_Unmount_).
* Folgende Möglichkeiten zum Einhängen:
[.step]
** beim Booten durch den `systemd`, Gerätedateien und zugehörige Mount Points müssen in der Datei `/etc/fstab` aufgelistet sein
** automatisch (durch einen Dämonen) beim Einlegen / Anschliessen des Datenträgers (CDs / DVDs, USB-Sticks, Wechselfestplatten), üblicherweise unter `/media` oder `/run/media`
** manuell mit dem `mount`-Befehl (z. B. `mount /dev/sdb1 /data`), Aushängen mit `umount`
* Aushängen ist nur möglich wenn niemand mehr auf Dateien / Verzeichnisse auf dem Datenträger zugreift (auch nicht als aktuelles Verzeichnis).

[.step]
* dienen dazu, auf möglichst einfache Weise und aus einer vertrauenswürdigen Quelle Software zu installieren (und zu deinstallieren)
* Die einzelnen Linux-Distributionen nutzen (zum Teil) unterschiedliche Paket-Manager, siehe https://www.linode.com/docs/guides/linux-package-management-overview/#comparison-of-package-managers[hier] für einen Vergleich.

== Paket-Manager - Konzepte
[.step]
* Software wird zu einem Paket zusammengefasst (ausführbare Programme, Bibliotheken, Skripte, Konfigurationsdateien) und ggf. für die Distribution angepasst (z. B. Dateipfade).
* Für jedes Paket werden Abhängigkeiten definiert (welche Pakete zusätzlich benötigt werden), die automatisch mitinstalliert werden (können).
* Es gibt ein sogenanntes _Repository_ mit allen verfügbaren Paketen (auf einem Installationsmedium wie CD / DVD / USB-Stick oder einem Server).
* Auf jedem System existiert eine Datenbank mit allen installierten Paketen.
* Alle installierten Pakete können mit einen Befehl aktualisiert werden, wobei Abhängigkeiten berücksichtigt werden (z. B. wenn eine bestimmte Software nicht mit der neuesten Version einer Bibliothek funktioniert).

== Troubleshooting (1)
[.step]

[source,sh]

== `/proc`-Dateisystem
[.step]
* ist ein _virtuelles_ Dateisystem, das vom Kernel zur Laufzeit des Systems angelegt und aktualisiert wird
* Inhalte, bereitgestellt in einzelnen Dateien, teilweise in Unterverzeichnissen:
[.step]
** Informationen zur Hardware wie CPU und Speicher (`/proc/cpuinfo` und `/proc/meminfo`)
** Informationen zu den laufenden Prozessen (ein Unterverzeichnis pro Prozess) wie die Befehlszeile, mit der der Prozess gestartet wurde (`/proc/<PID>/cmdline`) und die gesetzen Umgebungsvariablen (`/proc/<PID>/environ`)
** zur Laufzeit des Systems änderbare Kernel-Parameter wie z. B. Netzwerk-Einstellungen (`/proc/sys/...`)
* Dateien können mit `cat` gelesen und mit `echo ... > /proc/sys/...` verändert werden.
* hauptsächlich nützlich für Debugging und Troubleshooting

== Container
[.step]
* sind **virtuelle** Instanzen des Betriebssystems, die alle auf dem gleichen tatsächlich vorhandenen System laufen
[.step]
** nutzen alle den gleichen Kernel
** haben jeweils ein eigenes Dateisystem (dadurch sind unterschiedliche Distributionen möglich)
** haben jeweils einen eigenen _Namensraum_ für Prozesse (PIDs), Benutzer und das Netzwerk => Prozesse und Benutzer scheinen in einem Container "alleine" zu sein.
* verwendete Ressourcen (CPU, Speicher, Plattenplatz) können limitiert werden
* werden normalerweise mit Tools wie https://www.docker.com/[_Docker_], https://podman.io/[_Podman_] oder https://github.com/containerd/nerdctl[_nerdctl_] genutzt oder auch https://docs.docker.com/desktop/[_Docker Desktop_] oder https://podman-desktop.io/[_Podman Desktop_]
* Tools zum Verwalten einer grösseren Anzahl von Containern: https://docs.docker.com/compose/[_Docker Compose_] (eher für eine kleinere Zahl auf einem einzelnen Rechner, z. B. für die Entwicklung) oder https://kubernetes.io/[_Kubernetes_] (eher für eine grössere Zahl auf Clustern von Rechnern)


<<<
== Warum Container?
[.step]
* Applikationen können voneinander abgeschottet werden.
* Applikationen können "vorinstalliert", also zusammen mit notwendigen Bibliotheken, Konfigurationsdateien und einer evtl. notwendigen Laufzeitumgebung (wie die Java Virtual Machine oder der Python-Interpreter) ausgeliefert werden.
* Container sind leichtgewichtiger als virtuelle Maschinen und bieten unter Umständen weniger Angriffsfläche (weil sie nur die benötigten Programme und Daten enthalten).
* Container sind auch nützlich, um Testumgebungen / Testnetze auf einem einzelnen Rechner (z. B. eines Entwicklers) aufzubauen.


<<<
== Images
[.step]
* stellen das Dateisystem der Container in komprimierter Form dar (spezielle Form von `tar.gz`-Archiven)
* enthalten teilweise nur die Applikation mit ihren Abhängigkeiten (_Distroless_), oft wird aber eine Linux-Distribution als Basis benutzt (ist https://serverfault.com/a/951888[hier] gut erklärt)
* können selber erstellt (z. B. mit Docker oder Podman) und lokal gespeichert oder von _Container Registries_ wie z. B. https://hub.docker.com/[_Docker Hub_] heruntergeladen werden.
* _Dockerfiles_ sind die "Bauanleitungen" für Images
* Images sind nicht veränderbar => Änderungen in einem laufenden Container werden beim Beenden verworfen.

== _Optional_: Container ausführen (1)
[.step]
* Starten eines Containers: `podman run [Optionen] <Image>[:<Version>] [Befehl]`
* Wichtige Optionen:
+
|===

| `-d` | Container im Hintergrund starten
| `-it` | mit Standardeingabe und einem (Pseudo-)Terminal starten, für interaktive Nutzung, z. B. eine Shell
| `-v <Pfad auf dem Host>:<Pfad im Container>` | Verzeichnis auf dem Host im Container verfügbar machen, Pfade müssen absolut sein
| `-p <Port auf dem Host>:<Port im Container>` | geöffnete Netzwerk-Port(s) des Containers auf dem Host verfügbar machen
|===

== _Optional_: Container ausführen (2)
[.step]
* Laufende Container auflisten: `podman ps`
* Stoppen eines Containers: `podman kill <ID oder Name>`
* Programm (z. B. eine Shell) in einem laufenden Container starten:
[.step]
** Programm ist in dem Image des Containers vorhanden: `podman exec [-it] <ID oder Name> <Programm und Argumente>`
** Programm ist in dem Image des Containers **nicht** vorhanden: `nsenter -t $(podman inspect -f '{{.State.Pid}}' <ID oder Name>) <Namensraum> <Programm und Argumente>`

== Arbeiten mit Text - Suchen / Filtern (1)
* **Aufgabe**: Die Ausgabe von `journalctl` soll nach Logmeldungen von `systemd` gefiltert werden und die Anzahl dieser Meldungen soll gezählt werden.
* **Lösung**:
** mit `grep`, naiver Ansatz. Die ganze Zeile wird nach dem String `systemd` durchsucht, was zu falschen Treffern führen kann. Mit der Option `-c` bekommt man die Anzahl.
+
[source,sh]
----
$ sudo journalctl -S today | grep systemd
----

** mit `grep` und regulärem Ausdruck. Dadurch wird der String `systemd` nur gefunden wenn er als Programmname vorkommt.
+
[source,sh]
----
$ sudo journalctl -S today | grep -P 'systemd\[\d+\]'
----

== Arbeiten mit Text - Suchen / Filtern (2)
* **Lösung**:
** mit Perl. Nur die 5. Spalte, die den Programmnamen enthält, wird durchsucht. Man muss einen regulären Ausdruck verwenden weil `journalctl` an den Namen noch die PID anhängt. Mit einem `| wc -l` am Ende bekommt man die Anzahl.
+
[source,sh]
----
$ sudo journalctl -S today | perl -nale 'print if $F[4] =~ /systemd/'
----

** mit JSON und `jq`. Wenn man `| .MESSAGE` weglässt werden die kompletten Objekte mit allen Attributen ausgegeben.
+
[source,sh]
----
$ sudo journalctl -S today -o json | jq 'select(.SYSLOG_IDENTIFIER == "systemd") | .MESSAGE'
----

** mit JSON und DuckDB. Mit `select count(*)` bekommt man die Anzahl.
+
[source,sh]
----
$ sudo journalctl -S today -o json | \
    duckdb -c "select MESSAGE from read_json('/dev/stdin') where SYSLOG_IDENTIFIER = 'systemd';"
----

== Arbeiten mit Text - Aggregieren
* **Aufgabe**: Die Logmeldungen, die von `journalctl` ausgegeben werden, sollen nach dem Programm gruppiert und die Anzahl pro Programm absteigend sortiert ausgegeben werden.
* **Lösung**:
** mit Perl:
+
[source,sh]
----
$ sudo journalctl -S today | perl -nale 'print $F[4]' | sort | uniq -c | sort -rn
----

** mit Perl, Programmnamen ohne die PIDs:
+
[source,sh]
----
$ sudo journalctl -S today | perl -nale '$F[4] =~ /([a-zA-Z]+)/; print $1' | sort | uniq -c | sort -rn
----

** mit JSON und DuckDB:
+
[source,sh]
----
$ sudo journalctl -S today -o json | \
    duckdb -c "select SYSLOG_IDENTIFIER, count(*) from read_json('/dev/stdin') group by 1 order by 2 desc;"
----
